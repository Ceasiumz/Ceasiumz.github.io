# SimPatient Dental VR 用户视角系统设计报告

## 1. 范围与写作方式

本报告以 `release` 分支最新提交为唯一实现依据，说明学习者从启动 Demo、完成校准、进入牙科操作场景到结束会话的完整流程。写法参考 *When Seconds Count: Designing Real-Time VR Interventions for Stress Inoculation Training in Novice Physicians* 的 System and Implementation 部分：先交代用户流程和系统构成，再说明每段体验由哪些运行时模块实现。

文中“用户”指佩戴头显并使用双控制器的学习者；“实验人员”指负责启动 Demo、协助佩戴设备和保存会话数据的人员。报告只描述当前 `release` 可运行的技术流，不把其他分支中的场景、UI、事件或实验机制作为既有功能。

## 2. 系统概览

Demo 面向 Meta Quest 风格的头显与双控制器运行。用户在沉浸式牙科环境中调整自己与患者的相对位置，学习器械托盘、抓取、旋转、启动和归还动作，随后在正式场景中调节牙椅并操作牙科器械。系统在后台保存会话、关键交互事件与追踪轨迹，但记录过程不额外要求用户输入。

从进入应用到离开应用，默认路径如下：

```text
Control 启动与运行时管理器初始化
    ↓
Calibrate：位置校准、器械教程、正式器械校准
    ↓
Main：牙椅调整、器械操作与口腔观察
    ↓
左手 Menu 打开完成面板，确认完成并结束会话
```

运行时由 `Startup`、`Calibration` 和 `Experiment` 三个进程级状态构成。`Control` 首先建立场景管理、输入层、运行时校准存储及 Telemetry 管理器；准备完成后进入 `Calibrate`。用户在校准场景点击“开始操作”后，系统保存本次运行的校准值并加载 `Main`。状态切换采用目标场景先准备、成功后提交的方式，避免场景未准备好时离开当前步骤。

## 3. 用户会话流程

### 3.1 启动、佩戴与初始移动

实验人员从构建的首场景 `Control` 启动应用，协助用户正确佩戴头显、拿稳左右控制器，并确认控制器追踪有效。用户头部的真实平移和转动决定观察视角；左摇杆提供水平移动，右摇杆提供 45 度分段转向。移动方向基于头部在水平面上的朝向，因此用户可面向患者、托盘或牙椅工作区后再移动。

系统将移动、手部交互和用户界面输入分为独立输入层。当用户抓住器械并按住抓握键调节器械角度时，对应手的摇杆优先用于器械旋转，避免同时触发角色移动或转向。放下器械后，摇杆恢复通常的移动或转向用途。

### 3.2 位置校准与控制器认知

进入 `Calibrate` 后，用户看到欢迎说明，点击继续开始校准。系统随后短暂显示红色和蓝色标记，帮助用户理解左右控制器在虚拟空间中的实际跟踪位置。

接着，用户面对参考患者模型，以左摇杆进行水平调整，并以左手指定按钮调整高度，使患者处于舒适、可安全操作的范围。用户确认后，参考模型隐藏，系统进入器械交互教学。此处的位置增量会保存为运行时校准数据，之后加载正式场景时自动恢复。

### 3.3 器械托盘教程

系统将教程托盘固定在用户右侧附近，先说明器械存放位置，再依次引导以下动作：

1. 将控制器靠近超声洁治器并按下抓握键，取出器械。
2. 松开抓握键；如需改变持握角度，重新按住对应手的抓握键并推动该手摇杆。
3. 按下扳机键启动器械。
4. 将器械靠近空的托盘槽位，按抓握键将其归还。
5. 空手靠近托盘两侧边缘，观察手柄高亮，并按住抓握键移动托盘。

教程按实际交互事件推进，而非只按时间推进。用户必须成功取起、旋转、启动并放回教程器械，才会看到下一步提示。

### 3.4 正式器械校准

教程完成后，用户看到正式器械托盘与一个位于头显前方约 0.5 m、下方约 0.3 m 的校准点。用户逐一拿起托盘内器械，将工作端接触校准点；出现接触提示后，按持械手摇杆进入精细校准。此时用户可移动和转动手柄，使器械工作端与姿态符合个人舒适度，再次按摇杆完成当前器械的精细调整。

校准面板提供“重置”以清除本轮器械校准，并提供“完成”结束器械调整。用户最终看到“校准完成，可以开始操作”，点击“开始操作”后，系统保存玩家位置和每件器械的局部持握姿态，进入 `Main` 场景。开发期间可以用 `F8` 跳过教程直接进入正式器械校准；该快捷方式不属于常规用户路径。

## 4. 正式操作场景

### 4.1 工作区与患者姿态

`Main` 是默认实验子状态机加载的正式操作场景。用户进入后面向患者、牙椅、器械托盘和完成面板所在的工作区。牙椅控制面板支持连续调节椅位高度和靠背角度：用户按住相应控制按钮时，系统按固定速率改变高度或靠背的归一化位置；松开按钮即停止。患者模型随牙椅高度移动，靠背角度由患者 Animator 参数驱动。

高度和靠背值均限制在 0 到 1，避免连续输入产生超出预设范围的姿态。

### 4.2 近场拿取、持握与归还

每只虚拟手都有持续跟随控制器的近场交互区。用户靠近托盘槽位时，最近的可操作槽位进入高亮状态；按下抓握键，槽位中的器械会吸附到该手的持握锚点。用户将已持器械靠近空槽位后再次按抓握键，器械会回到该槽位的预设位置与旋转。

系统确保每件器械在任一时刻只由一个手槽或一个放置槽拥有。成功取起时，控制器提供双击触觉反馈；成功归还时提供金属触觉反馈。普通器械在持握时可采用直接跟手或顺应式物理跟手；后者保留工作端与牙齿、牙龈表面的受限碰撞，使用户不会完全刚性地穿过模型。

### 4.3 器械操作与即时反馈

通用器械基类统一处理持握、放置、扳机和持械摇杆事件：

| 用户动作 | 系统响应 |
| --- | --- |
| 靠近托盘槽位 | 显示该槽位的高亮状态 |
| 抓握槽位中的器械 | 器械附着到对应手部，并记录取起事件 |
| 按住抓握键并推动摇杆 | 绕器械局部 Z 轴调整持握角度 |
| 按下扳机 | 向当前器械发送启动动作；支持的器械开始工作 |
| 松开扳机或归还器械 | 停止当前器械的工作状态 |
| 工作端接触牙齿或牙龈 | 依据接触冲量、表面类别和滑动速度给出有限强度的触觉脉冲或摩擦反馈 |
牙科探针提供空间标记交互。用户持探针按下扳机时，系统检测工作端是否命中允许标记的牙面；命中后在该位置生成一次性视觉反馈，并发布带有命中空间信息的标记事件。该事件表示用户在该牙面执行了标记动作，不自动等同于诊断结论。

超声洁治器在扳机按下时显示喷水雾并进入使用状态；抛光器同样以扳机控制启停。口镜、吸唾器等器械使用相同的取放与持握框架。接触触觉区分牙齿与牙龈，并对持续接触进行低通与冷却处理，避免物理抖动造成密集的连续振动。


| 器械    | 工作细节                                                                            |
| ----- | ------------------------------------------------------------------------------- |
| 牙探针   | 接触口扫牙齿模型震动反馈，按下扳机标记牙石位置，数据记录牙石位置                                                |
| 超声洁治器 | 按下扳机启动水雾喷射干扰术野，同时触发震动反馈，球形sdf判定牙表面RT覆写，重新着色消除牙石。                                |
| 抛光器   | 按下扳机启动抛光器，同时触发震动反馈，球形sdf判定牙表面RT覆写，重新着色写入牙膏tex。                                  |
| 口镜    | 工作尖绑定平面镜，以centerEye为入射相机计算反射位置并写入平面镜表面baseTex RT，实现实时反射。                        |
| ~     | 把手使用capsule sdf计算接触表面threshold RT，avatarHead绑定threshold RT进行alpha切除模拟口镜的打开术野功能。 |
| 吸唾器   | 抓取吸唾器靠近avatar_head后出现四个放置位点，对术野造成不同区域的干扰。                                       |

## 5. 结束、重做与恢复

用户可通过左手控制器的 Menu 键打开完成面板。完成面板启动时保持隐藏，Menu 的按下沿只负责显示或隐藏该面板，因此用户可在操作中查看面板而不立即终止会话。用户点击“Complete And Exit”后，按钮变为不可再次点击，系统将会话标为完成并请求退出运行。

流程状态机还支持从正式操作返回校准，以及重新进入正式操作的内部事件路径，用于实验人员安排重做或重复体验。正常完成路径不要求用户手动处理状态机。

若应用在会话未结束时暂停、退出或异常中断，Telemetry 在下次打开数据库时会将遗留的“进行中”会话标记为中断，从而区分正常完成与非正常离开。

## 6. 数据记录与实现

`ControlSceneBootstrap` 在控制场景的其他管理器准备完成后创建并持久化 `TelemetryManager`、`TelemetryPoller` 与 `TelemetryEventBridge`。Telemetry 默认在 `Main` 场景加载时创建会话；记录过程不改变用户看到的场景、交互步骤或反馈。

每个会话包含以下四类数据：

| 数据表 | 记录内容 | 与用户流程的关系 |
| --- | --- | --- |
| `sessions` | 会话标识、参与者标识、程序与模式版本、开始/结束时间、状态与结束原因 | 确定一次体验的边界 |
| `trajectory` | 头显、左右控制器、当前持械工作端和口腔根节点的位置、旋转、朝向与追踪有效性 | 分析用户与工作区的相对运动 |
| `events` | 会话开始、任务开始/重做/完成、器械取起/归还/启停、对象放置等事件 | 还原离散操作顺序 |
| `results` | 是否完成、计时、重试次数和结束原因 | 区分完成、退出与中断 |

轨迹采样频率、是否记录各类实体和数据库位置由 `TelemetryConfig` 控制。系统只对当前被取起的器械记录工作端轨迹，以减少无关数据。事件桥接器监听全局交互事件并写入数据库；写入会按配置的时间间隔批量刷新，在应用暂停或结束时再执行一次刷新。

这些数据支持描述外显行为，例如用户何时取起器械、工作端在口腔附近停留多久、是否完成会话，或完成前是否发生重做。它们不单独证明用户的临床能力、诊断正确性或心理状态；相关结论需要结合任务规则、专家标注、经过验证的主观测量工具和研究方案。

## 7. 实施边界与真机验证

当前流程依赖真实头显追踪、控制器按键、近场碰撞、世界空间 UI 和触觉输出，因此应在 Android ARM64/IL2CPP 的 Quest 目标上完成最终验证。每次演示前，实验人员应检查：

- `Control`、`Calibrate`、`Main` 三个场景均可按顺序加载；
- 头显、双控制器和控制器追踪状态有效；
- 用户可移动、转向、取放器械、转动持械姿态并触发器械；
- 教程提示能在每个实际交互动作后推进；
- 位置与器械校准在进入 `Main` 后被恢复；
- 左手 Menu 可打开完成面板，完成按钮会结束且只结束一次会话；
- 数据库中可看到会话、事件、轨迹和结果记录，非正常结束会被标记为中断。
