# 论文技术报告 — 面向迁移训练的牙科临床检查 VR 系统

> **写作原则**：全文区分三类陈述。  
> **代码事实** — 当前仓库可复现的实现；**文档规划** — Prototyping / Phase5 设计意图；**建议实现** — 论文可用性所需、尚未完成的工程项。  
> 不得将规划或历史审阅报告当作已交付能力。

**工程基线（代码事实）**：Unity `6000.3.12f1`，URP `17.3.0`；Android ARM64 / IL2CPP，最低 API 32；Meta XR Core `205.0.0`，OpenXR `1.17.1`，XR Interaction Toolkit `3.3.1`，Input System `1.19.0`。运行时程序集 `SimPatient.Runtime`。构建首场景为 `Control`（持久管理器与 `GameFSM` 注入）。代表任务：超声龈上洁治 + 嵌入式临床检查（Phase 5 空间标记）。

## 1. 研究目标与需求映射

### 1.1 研究问题（文档规划）

| 编号 | 问题 | 系统侧含义 |
| --- | --- | --- |
| RQ1 | 迁移落差由哪些因素构成？ | 环境限制、患者自主反应、双重任务、完整流程分别对应哪些可观测行为 |
| RQ2 | 迁移导向 VR 应如何组合设计机制，且边界在何处？ | L1 可由 VR 独立承担；L2 需 Hybrid VR / 实体后测；L3 不可替代 |
| RQ3 | 训练效果、泛化与资源效率如何量化？ | 近迁移（未见 VR 情境）与远迁移（头模 / SP / OSCE 代理） |

### 1.2 八项设计目标 → 系统能力（代码事实 vs 规划）

| DG | 设计目标 | 当前系统覆盖（代码事实） | 论文中必须标明的缺口 |
| --- | --- | --- | --- |

| DG6 Layered feedback | 最小干扰可追溯 | 部分：空间标记无诊断语义（符合 Phase5）；遥测事件/轨迹 | 无危险即时中断规则、无训练后牙面时间轴复盘、无片段回放 |
| DG7 Accountable intelligence | 可审计治理 | 弱：原始事实表（sessions/trajectory/events/results）已存在 | 无教师结论表、无规则分析层、无 ASR 降级按钮；遥测桥与游戏流事件总线分离 |

**Phase 5 在框架中的位置（文档规划）**：不是独立诊断答题关，而是嵌入自然检查流程的行为观测。空间标记只表达“此处值得关注”，不代表诊断；评价应对准检查覆盖、顺序、定位与策略，而不是内部临床思维。

## 2. 总体软件架构

### 2.1 分层与依赖方向

```text
设备 (OVR / OpenXR)
    → Controllers（输入源、层仲裁、HandController）
        → Interactable（器械 / 托盘 / 近场抓取 / 牙面标记）
            → Events
                ├─ GameFSM.Instance.EventBus   （流程 + SpatialMark）
                └─ TypeEventSystem.Global        （器械遥测 Tool* 事件）
        → Managers / GameFSM（Startup → Calibration → Experiment）
        → Calibration（进程内持握校准）
        → Telemetry（SQLite）
        → DentalCleaningBridge（工具世界状态 → 渲染 Sink，当前无 ceasium Sink）
        → Graphics（UVSDF 绘制、网格跟随形变）
        → UI / Patient（托盘盘面、近场放大、牙椅与 BlendShape）
```

原则：**输入不进玩法模块直读 OVR**；器械 `ValidateGrab` 无副作用；标记资格只在 `DentalMarkSurface`；清洁渲染不轮询手柄。

### 2.2 模块职责与代码位置

| 模块 | 职责 | 关键类型 | 路径 |
| --- | --- | --- | --- |
| Controllers | XR 输入、Hand Slot、层优先级、右手 UI 射线 | `OvrRigController`, `HandController`, `InputControlLayerManager`, `OvrThumbstickRayController` | `Assets/Scripts/Controllers/` |
| Interactable | 抓取持有、托盘原子转移、探针标记、边缘抓取 | `InteractableInstrumentBase`, `InstrumentTraySlot`, `DentalExplorerInstrument`, `ShortRangeDentalSurfaceHitDetector` | `Assets/Scripts/Interactable/` |
| Managers / GameFSM | 事务性场景流 | `GameFSM`, `ControlSceneBootstrap`, `SimPatientSceneManager` | `Assets/Scripts/Managers/` |
| Events | 不可变流程/标记消息 | `SpatialMarkCreatedEvent`, `RequestGameStateTransitionEvent` | `Assets/Scripts/Events/` |
| Calibration | 属性级持握校准（内存） | `RuntimeCalibrationStore`, `[RuntimeCalibration]` | `Assets/Scripts/Calibration/` |
| Telemetry | 2 Hz 轨迹 + 工具事件 SQLite | `TelemetryManager`, `TelemetryPoller`, `TelemetryEventBridge` | `Assets/Scripts/Telemetry/` |
| DentalCleaningBridge | 渲染中立工具快照 | `DentalCleaningToolState`, `DentalCleaningToolBridge` | `Assets/Scripts/DentalCleaningBridge/` |

### 2.3 全局流程（代码事实）

合法转移：`Startup → Calibration → Experiment`，`Experiment → Calibration`，`Experiment → Experiment`。目标场景在源状态退出前准备；失败则源状态与订阅保持。实验准备走缓存的 experiment sub-FSM，不每轮新建。场景加载只经 `IGameSceneLoader` / `SimPatientSceneManager`。

## 3. 关键算法与实现细节

### 3.1 Hand Slot 与抓取

世界位姿（`HandController.cs`）：

```text
slotRotation = controllerRotation * localPose.Rotation
slotPosition = controllerPosition + slotRotation * localPose.Offset
```

抓取：空手且 Grip/扳机边沿满足时 `Physics.OverlapSphereNonAlloc`（固定缓冲），按到球心距离排序，`ValidateGrab` 通过后注入：可选 Rigidbody 改为 kinematic、关重力、父到 Hand Slot、应用持握局部位姿。持有后扳机转发到器械；托盘目标上的完整握持手势优先于器械旋转。

**与 2026-07-29 审阅的差异（代码事实）**：托盘占用/放置已实现且要求原子转移；工程内已有多类 `InteractableInstrumentBase` 派生器械。历史文档中“放下抛 NotImplementedException / 无派生器械”不再成立。

### 3.2 空间标记检测（Phase 5 基线）

合同：`IDentalSurfaceHitDetector.TryDetect(out DentalSurfaceHit)`。器械不直接调用 Physics。

`ShortRangeDentalSurfaceHitDetector`：从 `WorkingTip` 做一次 `SphereCastNonAlloc`。默认半径 `0.001 m`，最大距离 `0.015 m`，`QueryTriggerInteraction.Ignore`，方向为检测器局部向量变换到世界并归一化。缓冲容量 16；装满则开发期警告。筛选：LayerMask → 父级 `DentalMarkSurface` → `Accepts(collider)`，取最近合法命中。返回世界点、法线、距离、Surface 引用（事件侧带 `SurfaceId`）。

**调用频率**：仅扳机按下边沿一次；禁止 `Update` 持续查询。未命中安静返回。

### 3.3 标记确认与事件

`DentalExplorerInstrument.OnTriggerButtonPressed`：配置校验 → `TryDetect` → 实例化 `SurfaceMarkFeedback.Play(hit)` → `GameFSM.Instance.EventBus.Send(SpatialMarkCreatedEvent)`。按住不连发由 `HandController` 边沿保证；释放不标记。首次有效标记时向 **Global** 发 `ToolActivatedEvent`，释放发 `ToolDeactivatedEvent`（供现有遥测桥）。

`SurfaceMarkFeedback`：短时、无诊断语义、挂到命中 Transform 下随口腔运动。

### 3.4 超声洁治与清洁桥

`UltrasonicCleaner`：扳机按下开启清洗/水雾，释放/放回托盘/Disable 关闭，并经 Global 发 activate/deactivate。

`DentalCleaningToolState`：世界坐标、内外半径、`IsActive`。`EmissionEnabled` 须由器械语义边沿打开，持有本身不等于激活。本仓库 **无** ceasium Shader/RT Sink；`UVSDFPainter` 仍是独立 Graphics 路径（每帧 `PaintOnce`，含历史鼠标调试残留），**不能**等同于已闭环的牙石减少量化。

`RuntimeSurfaceDeform`：点到源网格最近三角形（线性扫三角形），绑定后 LateUpdate 跟随。复杂网格建议 BVH（建议实现，非现状）。

### 3.5 校准与时钟

`RuntimeCalibrationStore` 挂在 Control，**仅当前进程**。`[RuntimeCalibration(稳定 ID)]` 属性在离开 Calibrate 时显式 Save，目标 `Awake` Restore。无文件 schema 版本化持久化。

`TelemetryClock` 提供会话内 elapsed；`TelemetryPoller` 默认 `pollingRateHz = 2`。

### 3.6 事件总线分裂（论文必须写清）

| 通道 | 用途 | 订阅方 |
| --- | --- | --- |
| `GameFSM.Instance.EventBus` | 场景流、校准完成、**空间标记** | GameFSM 状态、测试监听器 |
| `TypeEventSystem.Global` | `ToolGrabbed/Released/Activated/...`、Session 遥测 | `TelemetryEventBridge` |

**代码事实**：`TelemetryEventBridge` **未**订阅 `SpatialMarkCreatedEvent`。标记不会自动入库。这是设计上的预留接入点，不是已完成采集。

## 4. Phase 5 流程设计（闭环）

### 4.1 一次标记（已实现交互）

```text
托盘取探针（HandController + InstrumentTraySlot）
    → 工作端对准牙面（WorkingTip + 检测器局部方向）
    → 扳机按下边沿
    → SphereCast 一次
    → 未命中：无光环、无事件
    → 命中：光环 + SpatialMarkCreatedEvent
    → 继续检查
```

目标契约：可整体移动的根 + `DentalMarkSurface` + 白名单 Collider。探针不引用患者骨骼或场景名。当前上颌多为整网，**不能**从命中可靠解析牙位/牙面（规划中的目标侧拆分）。

### 4.2 设计上的后台记录（规划，大部分未接库）

| 规划数据类型 | 现状 |
| --- | --- |
| 观察/视野覆盖 | 未实现 |
| 接近、接触、停留、扫查 | 仅 2 Hz 工作端位姿，无接触分段算法 |
| 空间标记 | 仅内存事件；无 SQLite 行 |
| 检查顺序 / 重复检查 | 可事后由轨迹+标记离线算，运行时无 |
| 治疗后续 | 超声激活事件在 Global；与标记无关联表 |

### 4.3 科研解释边界（规划，写入论文局限性）

可评价外显检查与关注锚点；**不可**仅凭 VR 轨迹声称识别内部临床思维。

## 5. 数据采集与存储策略

### 5.1 已实现 schema（`TelemetryModels.cs`，schema_version 默认 2）

**sessions**：`session_id`, `participant_id`, `program_version`, `schema_version`, `start_utc`, `end_utc`, `status`, `end_reason`。

**trajectory**：`elapsed_time`, `entity_type`（Hmd / Left / Right / Tool / MouthRoot）, `entity_id`, 位置、四元数、forward、`tracking_valid`。

**events**：`event_type`, `tool_id`, `target_id`, `value_1/2`, `payload_json`。

**results**：`completed`, `duration`, `retry_count`, `end_reason`。

Poller 实体：HMD、左右控制器、嘴部根（`TelemetryMouthRootReference`）、当前已登记活动器械的 WorkingTip。

### 5.2 路径与 Android（代码事实）

`TelemetryConfig.ResolveDatabasePath()`：相对路径拼到 `Application.persistentDataPath`；绝对路径原样使用。

**资产事实**：`Assets/Resources/TelemetryConfig.asset` 中 `databaseDirectory` 仍为 `D:/dental_dataset`。Quest/Android **必须**改为相对目录（如 `Telemetry`）或运行时覆盖，否则无法写入。代码已支持相对路径，**配置未改**。

### 5.3 建议入库的 SpatialMark 字段（建议实现）

`session_id`, `elapsed_time` 或 `timestamp_utc`, `instrument_id`, `hand`, `surface_id`, `world_pos`, `world_normal`, `local_pos`, `distance`, `event_index`；分析阶段再关联 `case_id` / `level_id` / `game_state`（当前会话表无这些列）。

教师结论必须另表且系统不可覆盖（DG7，未实现）。

### 5.4 隐私与导出

实验默认匿名 `participant_id`；不采集 PII。导出（SQLite→CSV/JSON、Quest 分享）为建议实现。语音/录像若引入须伦理与脱敏条款。

## 6. 验证计划与度量

### 6.1 自动化测试（代码事实，项目自有程序集）

不跑第三方包测试。变更后经 Unity-Skills 刷新编译再跑受影响夹具。

### 6.2 真机验证（建议记录进附录）

Quest：取放探针 → 15 mm 内标记稳定、牙龈/空气无光环、光环随口腔、无持续 Physics、无异常 GC。至少 3–5 pilot + 10 连续 Session 无串场（对应 DG2 验收，**尚未作为已通过证据**）。

### 6.3 论文指标（规划；依赖标记入库与离线分析）

检查覆盖率、首次发现到标记时间、与专家区域的空间命中（区域而非单点）、重复检查率、接触时长、路径效率、安全暂停/教师介入次数、未见情境完成率。统计：以 Case/Level 为因素的混合效应模型（方法章展开）。**当前运行时不算这些指标。**

## 7. 已实现 / 未实现与风险

### 7.1 可直接引用的代码事实

- `SimPatient.Runtime` 分层、`GameFSM` 事务流、输入层仲裁、HandController 抓取与托盘原子转移  
- 多器械派生类、探针 Phase5 闭环（检测、光环、EventBus 事件）  
- 遥测 SQLite 四表、2 Hz 轨迹、Global 工具事件桥  
- 清洁桥合同、超声扳机水雾、顺应持握与接触触觉组件、近场放大与托盘 UI  

### 7.2 不得声称已完成

- 语音/对话、叫停与信任状态、病例与 Level 参数化、牙位牙面解析  
- SpatialMark → SQLite、Android 导出、AI 评分、校准落盘  
- 牙石减少/覆盖地图量化、完整洁治物理闭环、长期迁移数据、ceasium Sink 合并  

### 7.3 风险

1. **TelemetryConfig.asset 绝对路径** 阻断 Quest 采集。  
2. **双总线** 导致标记与工具事件无法同一订阅器处理。  
3. 文档漂移：`InstrumentInteractionChainReview.md`、部分 Phase5 计划句（“本轮不实现记录器”）与后续遥测模块并存，引用时写清日期与核验路径。  
4. `UVSDFPainter` / `RuntimeSurfaceDeform` 在复杂网格上的性能。  
5. `TelemetryEventBridge` 使用 Global，与运行时 AGENTS 对游戏流“禁止 Global”的约定不一致——遥测是既成例外，论文中应如实描述而非掩饰。
